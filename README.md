# Brightloop Software — Subscription Management & Recurring Billing System

An enterprise subscription lifecycle management and automated recurring billing system built for the Brightloop hackathon challenge. Conforms strictly to the canonical specifications in [`docs/`](./docs).

---

## 5-Command Quick Start

```bash
# 1. Start PostgreSQL via Docker
docker compose up -d

# 2. Setup backend dependencies and database schema
cd backend && npm install && npx prisma migrate dev && npm run seed

# 3. Setup frontend dependencies
cd ../frontend && npm install

# 4. Start backend server (port 5000)
npm --prefix ../backend run dev

# 5. Start frontend app (port 3000)
npm --prefix ../frontend run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

## Key Architecture & Features

### 1. Automated Recurring Billing Engine (`B2-4`)
- **Strict Idempotency:** Guarded by database unique constraint `@@unique([subscriptionId, periodStart, periodEnd])`. Re-running billing for the same date range skips existing periods without duplicate charges.
- **Missed Periods Catch-Up:** Automatically catches up missed billing intervals in sequential order.
- **Row-Level Concurrency:** Applies row locks during transactional invoice generation.
- **Automated Expiry & Auto-Close:** Background cron job triggers `runBilling()` and closes expired subscriptions configured with `plan.autoCloseAtEnd = true`.

### 2. Quotation to Subscription Lifecycle (`B2-2`, `B2-3`)
- **Strict State Machine:** `DRAFT` $\rightarrow$ `QUOTATION` $\rightarrow$ `CONFIRMED` $\rightarrow$ `ACTIVE` $\rightarrow$ `CLOSED`.
- **Policy Enforcement:** Dynamic action buttons and API validations respect plan flags: `pausable`, `renewable`, `closableEarly`, and `autoCloseAtEnd`.
- **Audit History:** Every transition records a `StatusHistory` timeline entry with actor details and timestamps.

### 3. Precision Financial Calculations (`B2-1`, `B2-5`, `B2-6`)
- **Deterministic Math:** Money values stored as `Decimal(12,2)`.
- **Discount Allocation:** Supports percentage and proportional fixed discounts split across eligible items. Tax calculations are computed strictly **after** discount deductions.
- **Invoice & Payments:** Invoices can only be generated by the billing engine (no manual creation). Confirm, cancel, email, and streaming PDF invoices with balance settlement.

### 4. Executive Finance Dashboard (`B2-7`)
- Real-time SQL aggregations for active subscriptions, cleared cash receipts, pending receivables, and overdue amounts with days overdue metrics.
- Interactive Recharts breakdowns for revenue vs. exposure and payment channels.

### 5. Multi-Tenant Customer Portal (`B2-8`)
- Scoped to `req.user.customerId`. Attempting to access another customer's subscription or invoice returns a `404 Not Found` to prevent data leakage.

## Verification & Tests

### Backend Unit & Integration Tests (29 tests)
```bash
npm --prefix backend test
```
Covers:
- `billing.test.js`: Idempotency, missed-period catch-up, discount limit exhaustion, paused subscriptions, and expired discounts.
- `billing.calculator.test.js`: Proportional discount allocation, multi-tax calculation, and post-discount tax math.
- `discount.test.js`: Eligibility engine and usage limits.
- `auth.test.js`: 9+ character password rules and atomic customer creation.

Compiles and generates all 31 static and dynamic Next.js routes with zero TypeScript errors.
